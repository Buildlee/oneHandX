# 动作序列与动作面板（v0.7.0-dev）

> 本次把「一个手势只能绑一个动作」升级为「一个手势可绑一串动作」，并新增可自定义按钮的「动作面板」。
> 全部改动在分支 `feat/handle-groups`，未触碰并行会话的 `feat/temporary-edge-takeover`。

## 1. 动作序列

### 数据模型
- 槽位键沿用 `act_<handleId>-<len>-<dir>`：`len ∈ S|L|H`，`dir ∈ H|U|D|VU|VD`；另有 `-P`（原地长按）、`-C`（单击）、`-W`（双击）。
- 新增 `seq_<slot>`：多行文本，每行 `动作id \t 包名 \t 名称`，字段内 `\t`、`\n`、`\\` 转义（SharedPreferences 以 XML 持久化，不能存裸控制字符）。
- 写入时把**首步**同步到 `act_/pkg_/label_`：
  - 旧代码、备份（`dumpJson/applyJson`）与快速工具面板读到的仍是合法单动作；
  - 单步时删除 `seq_`，即完全退回旧格式；
  - 清空时写入 `act_ = none`（不能直接删键，否则 `-S-H` 会回落成默认「返回」）。
- 读取 `Prefs.steps(slot)`：有 `seq_` 用序列，没有就把 `act_` 当作 1 步，因此**旧配置无需迁移**。

### 编辑
手柄编辑页 → 点任意手势行 → 「动作序列」页：

| 操作 | 说明 |
|---|---|
| 添加动作 | 追加到末尾；选「打开应用」会跳到应用选择器并追加 |
| 点按某一步 | 用动作选择器替换该步 |
| ↑ / ↓ | 调整执行顺序，首/末项置灰 |
| ✕ | 删除该步 |
| 清空动作序列 | 二次确认后清空，该手势不再触发 |

### 执行
`EdgeService.runSteps()` 逐步执行，步间隔 **150ms**，逐步写日志：

```
seq slot=L1-S-H step=1/3 action=home ok=true
seq slot=L1-S-H step=2/3 action=notifications ok=true
seq slot=L1-S-H step=3/3 action=volume_up ok=true
```

单步失败不中断后续；最后一步完成后才震动反馈。

## 2. 动作面板

- 新动作 `action_panel`（「动作面板」），归入「面板」类，不能被塞进别的面板（防递归）。
- 入口：面板 → 动作面板（8 个按钮，前 8 个已配置的才显示）。
- 两种排布（可在页面顶部切换）：

| 样式 | 形态 | 说明 |
|---|---|---|
| 文件夹 | 贴边卡片，2 列网格 + 「关闭面板」 | 默认；信息密度高，适合 6–8 个按钮 |
| 扇形 | 全屏遮罩 + 以屏幕边缘为圆心的弧线排布 | 圆弧半径 `140+18n`dp、张开角 `min(110, 18+13n)`°，带弧线引导和「点按空白处关闭」 |

- 点击即执行并写日志 `panel item=<序号> action=<id> ok=<bool>`；15 秒未操作自动关闭；点空白处关闭。
- 未配置任何按钮时 Toast 提示去配置。

## 3. 实测证据

环境：`emulator-5556`（Android 16，1080×2400 @420dpi），debug APK `versionCode 10 / 0.7.0-dev`。

| 用例 | 操作 | 结果 |
|---|---|---|
| 三步序列执行 | 设置页水平滑动（`home → notifications → volume_up`） | `step=1/3 home ok=true`、`step=2/3 notifications ok=true`、`step=3/3 volume_up ok=true` |
| 序列展示 | 手柄编辑页手势行 | 右侧显示「主屏幕 · 共 2 个动作」 |
| 编辑页 | 进入「动作序列」 | 标题、`共 2 个动作 · 从上到下依次执行`、序号/动作名/↑↓✕ 均正确 |
| 追加动作 | 添加动作 → 媒体 → 音量 + | `seq_L1-S-H` 变为 3 步；页面显示「共 3 个动作」 |
| 调整顺序 | 第 1 行 ↓ | `seq` 变为 `notifications, home, volume_up` |
| 删除步骤 | 第 3 行 ✕ | `seq` 回到 2 步 |
| 文件夹面板 | 上滑唤出 → 点「截图」 | `panel item=3 action=screenshot ok=true`，`/sdcard/Pictures/Screenshots` 出现新文件 |
| 文件夹面板（第 2 列） | 点「最近任务」 | `panel item=2 action=recents ok=true` |
| 扇形面板 | `panel_style=1`，上滑唤出（4 按钮） | `panel shown mode=actions style=fan side=L n=4`；点第 2 个 → `panel item=2 action=recents ok=true` |
| 旧配置兼容 | 无 `seq_` 的默认槽位 | 仍按单动作执行，日志格式不变 |

截图：`work/gulu-ui/panel-fan-4items_s.png`、`panel-folder_s.png`、`ui-sloteditor6_s.png`、`ui-actionpanel-config_s.png`。

## 4. 已知限制

1. 扇形按钮越多，弧线越紧；实测 4 个最舒展，8 个属于密度上限。
2. 面板内**不提供**面板类动作（避免递归）。
3. 动作间隔固定 150ms，不支持逐条自定义（保持实现简单）。
4. 设备拦截系统动作（如 ColorOS 的 `performGlobalAction` 返回 false）时，序列会继续执行后续步骤，日志里能看到 `ok=false`。
5. 动作序列不支持条件或参数（如「按住时长」），只做顺序执行。
