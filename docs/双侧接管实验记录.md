# 双侧临时接管：模拟器实验记录

本分支实现中的功能遵循任务目录的《双侧临时接管实施方案 v2》。这是开发中的调试功能，不是正式发布版本；入口只在可调试的 Android 模拟器上显示，不对真机开放。已发布的 v0.6.1 仍使用手势共存模式。

## 当前实现

- 使用 Shizuku shell UserService 临时写入当前用户的左右返回热区设置；试用限时 30 秒，左右边缘均须实际完成校准，用户确认后才持续接管。
- 接管前保存原始值，通过应用自身权限实际演练本地恢复，再创建新的试用事务。独立的「恢复系统手势」桌面入口运行于独立进程，可在 Shizuku 不在线时使用已授予的本地权限恢复。
- 主线程健康心跳、守护超时、取消标记和跨进程锁用于处理故障；输入法、锁屏、排除应用等场景先归还系统，条件满足后重新申请。底部主页和多任务不由应用接管。
- 恢复按左右原值分别处理；外部改动的值不会被直接覆盖。故障时保留恢复记录，不以设置写入成功代替真实手势验证。

Shizuku 停止时其 UserService 可能一起退出，独立恢复进程也不能抵抗卸载或清除应用数据。恢复权限被撤销、应用数据不可用、外部存储锁不可用，或系统设置调用超时且无法确认已停止时，恢复不能保证成功。预留权限为系统级 `WRITE_SECURE_SETTINGS`，范围不限于手势；实现代码只使用固定的两个手势设置键。

## 已验证

隔离环境为 Android 16 / API 36 模拟器（1080 × 2400，420 dpi），Shizuku 13.6.0；不代表其他模拟器版本或手机厂商兼容。

- 构建通过；恢复数据与边界测试 25 项、Shizuku 和事务检查 46 项；守护超时恢复做过 30 次循环。
- 左右各三个滑动方向、手柄外返回、拖回取消、30 秒试用、正常停止、底部主页与多任务经过模拟器操作验证。
- 测试过应用强制停止、Shizuku 停止、锁屏、键盘、旋转、应用排除及导航方式变化等场景；独立恢复页在接管期间可恢复设置，左右系统返回均实际触发。
- 模拟器重启及应用更新后的自动恢复经过独立实验；广播不是必达保障。原值为空和左右不对称的原值均做过恢复检查。
- 现有功能浅色及深色回归各 56 项，动效检查 27 项通过。

测试结束后已归还模拟器的原始系统设置、辅助服务配置和临时授权。部分故障测试的耗时只反映该模拟器当次结果，不构成时限保证。

## 尚未完成

Android 13 / 15 覆盖、两小时持续切换及待机、真实主线程 ANR、完整的写入超时与延迟副作用注入、存储满、卸载/清除数据后的外部恢复、恢复资料导出及高刷真机校准尚未完成。系统设置调用超时后的潜在延迟写入仍需进一步处理与验证，因此不能声称所有竞态都已安全解决。恢复入口的可达性目前由用户手动确认，不能证明所有厂商桌面均可访问。

在这些验收完成并经对应设备校准之前，不开放真机双侧接管，不发正式版。调试 APK 可用于模拟器开发，不能作为正式安装包推荐。

## 构建

使用工程现有 JDK 17、Android SDK 和 Gradle wrapper：

```powershell
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest
```

实验依赖固定为 Shizuku API / Provider 13.1.5，许可证见 [第三方声明](../THIRD-PARTY-NOTICES.md)。
