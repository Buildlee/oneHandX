# 手柄组与删除交互（v0.6.2-dev · 参考 gulugulu）

## 为什么改

旧版把左右手柄当作两套独立列表：每侧各自计数（`handle_count_L/R` 1..3），删除入口只在「非第 1 个且恰好是最后一个」时出现。结果：

- 想删第 1 个或中间的手柄，没有入口；
- 单边增删后左右数量不一致，编号与预期错位；
- 没有「复制到对侧」，左右映射只能手配；
- 删除无撤销。

## 新模型：手柄组

- **一组 = 左 + 右**。组号 1..3，两侧永远同时存在；不想要某一侧时用「该侧停用」，而不是删除数据。
- 存储仍沿用 `h_L1_* / h_R1_*` 与 `act_*` 槽位键，只增加 `group_count` 与 `groups_model` 两个键，迁移不重写既有数据。
- 迁移规则：`group_count = max(旧 count_L, 旧 count_R)`；旧数据缺少的一侧标记为停用（`h_<id>_enabled=false`），原有长度、位置、映射全部保留。
- 备份 JSON 自动包含新键（`expectedType` 已登记 `group_count` / `groups_model`）。

## 交互

| 位置 | 操作 |
|---|---|
| 首页 | 每行一个「手柄组 N」，副标题显示 `左 · 长 70% · 位 50% ｜ 右 · 已停用` |
| 首页行尾 `⋯` | 编辑左手柄 / 编辑右手柄 / 复制左手柄到右手柄 / 复制右手柄到左手柄 / 删除手柄组 |
| 首页 | 「＋ 添加手柄组」左右同时新增；至少保留 1 组 |
| 编辑页顶部 | 「左手柄 / 右手柄」切换；「复制到对侧」（两个方向） |
| 编辑页底部 | 「删除手柄组 N」常显；两侧启用时副标题为「将同时删除左手柄和右手柄」 |
| 删除确认 | 两侧启用：「将同时删除左手柄和右手柄，是否继续？」；仅一侧：「将删除该手柄，是否继续？」 |
| 撤销 | 删除后首页顶部出现「已删除「手柄组 N」· 点按撤销（30 秒内有效）」，恢复删除前的完整快照 |

## 实现要点

- `Prefs.deleteGroup(index)`：把 index 之后的组整体前移（迁移 `h_*/act_*/pkg_*/label_*` 四类键），再删除末尾组；`group_count` 与两侧计数同步。
- `Prefs.copySideToOther(index, side)`：复制 `_enabled/_len/_pos/_alpha/_priority_dp` 与全部手势槽位（含长按）。
- `Prefs.beginUndo()/performUndo()/hasUndo()`：删除前对 `SharedPreferences.getAll()` 做快照，撤销时整体写回；不落盘，进程重启即失效（符合一次性撤销语义）。
- 服务侧无需改动：`handleCount(side)` 在存在 `group_count` 时以组数为准，窗口按组×侧生成。

## 验证（模拟器 OneHandTest · Android 16）

| 用例 | 结果 |
|---|---|
| 旧数据迁移（L=2 / R=1） | `group_count=2`、`h_R2_enabled=false`、原映射保留 |
| 首页列表 | 两组，副标题 `左 · 长 70% · 位 50% ｜ 右 · 已停用` |
| 删除组（任意位置） | 组 1 → `group_count=1`，左右数据同时移除 |
| 撤销 | 恢复 `group_count=2`，`act_L1-S-U=notifications` / `act_R1-S-U=home` 原样回来 |
| 复制左手柄→右手柄 | `act_R1-S-U=notifications`、`act_R1-S-D=recents` |
| 新增组 / 删除末组 | 3 组 ↔ 2 组，两侧开关正确 |
| 服务窗口 | 2 组且右侧停用 → 无障碍浮层窗口数 = 3（L1/R1/L2） |

## 兼容与边界

- 仍然只是「左右手柄」，不含 gulugulu 的底部/顶部触钮（列为后续 P2）。
- 删除只影响手柄与映射，不动全局设置；撤销为 30 秒内一次性回滚。
